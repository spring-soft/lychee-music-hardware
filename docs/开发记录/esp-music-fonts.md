**2026-09-25 把字库从 GB2312 补到 CJK 全集。** 起因：用户发现日文歌名显示成 `紅?呪?`
（**GB2312 里根本没有假名**），并且要求"字库补全，flash 空间挺足的"。

**Why:** 这里有两个反直觉的点 —— ① "flash 足"其实不够，**瓶颈是 assets 分区只有 2MB**；
② 字库变大不只吃 flash，**还吃 RAM**（LVGL binfont 要为每个字形建描述表）。

**How to apply：**

**⚠️ 0. 先看这条：当初"CJK 全集必然坏"的判断后来被证伪了**
2026-09-25 把字库扩到 CJK 全集（28080 字形）后用户报"中文变成看不懂的字"，
我当时判断是字库坏了、退回 GB2312+假名。**但这个判断后来被证伪** ——
用 1:1 像素回读 + PIL 参考图对比（IoU 63%）确认**两个字号的字形都是对的**
（16px「爱」、12px「王」都渲染正确）。**那次回退可能是没必要的。**
现在状态：GB2312 + 假名，**两个字号都改成 4bpp**（16px 837KB、12px 519KB），
小字清晰度明显好于 2bpp —— **用户确认"字体正常了"，问题解决了。**
⚠️ 我无法区分是"退回小字符集"还是"提到 4bpp"起的作用；从证据看 **4bpp 更可能是关键**
（2bpp/4bpp 下字形都是对的，区别只在笔画的灰度表达能力：**2bpp 的 4 级灰度会把汉字细笔画
量化掉/粘连，丢了笔画就成了"别的字"**）。**结论：中文点阵至少 4bpp，12px 及以下尤其必须。**
要再试 CJK 全集（4bpp），先读 [[esp-music-screen-readback]] 的对比方法，边扩边验收，别靠猜。

**1. 分区先扩容（否则怎么做都放不下）**
`assets` **2MB → 4MB**，`cache` 相应 7.875MB → 6.125MB：
```csv
assets, data, spiffs, 0x620000, 0x400000,
cache,  data, fat,    0xA20000, 0x5E0000,
```
assets 起始偏移 `0x620000` **没动**，所以 app/引导区布局不受影响；
cache 本来就是空的（M6 才用），6MB 依然远超需要。
✅ 实测 4MB 分区的 `esp_partition_mmap` 正常（日志 `数据 3283 KB @ 0x3ca10000`）。

**2. ⚠️ 字符集只列【字体真有的】Unicode 块 —— 实测 DroidSansFallbackFull 只有这些**
```bash
# tools/gen_font.sh 的 RANGES
0x4E00-0x9FFF  # CJK 统一表意文字 20992 字（简体+繁体全覆盖）
0x3400-0x4DBF  # CJK 扩展 A 6582 字（生僻字）
0x3040-0x309F  # 平假名   ← GB2312 没有它，日文歌名以前全是 ?
0x30A0-0x30FF  # 片假名
0x3000-0x303F  # CJK 标点（、。《》「」【】）
0xFF00-0xFFEF  # 全角 ASCII + 半角片假名
```
**这个字体里【空】的范围**（逐块探过）：
`0x2010-0x2027`（— …）、`0x2190-0x21FF`（箭头）、`0x2200-0x22FF`（≈ ± −）、
`0x23E9-0x23FA`（媒体控制）、`0x25A0-0x25FF`（★ ▶ ● ■）、`0x2600-0x26FF`（♪ ♫）、
`0x2700-0x27BF`、`0x00B0-0x00B7`、`0x0400-0x04FF`（西里尔）、`0x31F0-0x31FF`。
⚠️ **这些字符要么靠 LVGL 内置 Montserrat 兜底（ASCII / Latin-1 / 西文标点），
要么走预渲染图片**（★ ▶ 这些界面图标本来就用的 assets 里的 PNG，不靠字形）。
⚠️ `lv_font_conv` 对"整段一个字都没有"的 range 会**直接报错退出**，
但混在大字符集里时是**静默跳过** —— 所以老 `charset.txt` 里写着有 `—` `…`、字体里其实没有，
屏上就是方框/空白。**这个文件误导过一次排查，现在它由 RANGES 推导生成、与字体严格一致。**

**2.5 4bpp 比 2bpp 值**：2bpp 只有 4 级灰度，12px 汉字笔画糊成一团。
assets 分区扩到 4MB 后放得下（16px 837KB + 12px 519KB，加图和网页共 1.74MB）。

**3. ⚠️⚠️ 代价：字库吃 RAM，约 24 字节/字形**
实测 `lv_binfont_create_from_buffer` 之后 **PSRAM 空闲从 7097KB 降到 4882KB（−2.2MB）**，
而 assets 只增加了 2.1MB —— 也就是**这套字库把 flash 的空间又吃了一份到 PSRAM**：
`28080 字形 × 2 套字号 × ~24 字节 ≈ 1.35MB` 的字形描述表，加上 cmap/kern 数组 ≈ 2.2MB。
**日志上写的"零拷贝"指的是字形位图不拷贝**（那些还在 flash 里按需读），
**字形描述表仍然要在 RAM 里建** —— 别被"零拷贝"骗了。
当前 PSRAM 还剩 4.8MB，够用；但**要再扩字库（比如加 CJK 扩展 B、韩文）就得先算这笔 RAM 账**。
生成耗时：**每个字号约 1 分 50 秒**（28k 字形）。

**4. 顺带修的真 bug：`LV_LABEL_LONG_MODE_DOTS` 会【折行】**
用户报"列表里歌名过长就会换行挡住下面"。根因：**DOTS 是"折行 + 在最后一行末尾加省略号"，
不是"单行省略"**。只限宽度不限高度的话，字多了就折成两三行盖住下面的行。
**正确做法：同时把高度限成一行**（`components/ui/src/ui.c` 的 `ui_put_label_1line()`）：
```c
lv_obj_t *l = ui_put_label(..., LV_LABEL_LONG_MODE_DOTS);
lv_obj_set_height(l, lv_font_get_line_height(font));   /* ← 这一行是关键 */
```
列表行 / 菜单行 / 信息行 / 提示条 / 启动页文字全改成了这个包装函数。
**换字库后必看行高**（已加永久启动日志）：
```
行高: 16px=18  12px=14  拉丁12=15 ｜ 行距: 列表22 菜单17 信息15
```
都还放得下一行（列表 22>18、菜单 17>14+1、信息 15>14）。
**调整行距或换字号时，先看这行日志再改 `ui_pages.c` 里的 ROW_H。**

**5. 端到端验证手法（造数据打真机）**
用 `POST /api/play {"id":..,"title":"<要测的字>","artist":".."}` 直接把标题送进去，
配合串口的 `屏上显示: 歌名="..."` 与 `[字库] 缺字形 U+%04X` 两行日志判读。
⚠️ **id 必须在当前队列【之外】才走这条快路径**；已在队列里会走"跳过去"分支、
**忽略你给的元数据**（这个坑我踩了两次，每次白测一轮）。拿队列外的 id 用 `/api/search?q=`
—— 但**同一个 id 用第二次就进队列了**，所以每测一条都要换一个查询词。
实测通过：`㐀㲎生僻字测试`（扩展 A）、`龘靐齉爩`（CJK 极生僻）、`紅い呪い`/`ヨルシカ`（假名）。

**6. ⚠️⚠️ 还有第三类坑：码点在、字形是【空的】—— 2026-09-25 才发现**
以前只知道两类：`字体里没有 → 屏上一片空白`、`charset.txt 说有但字体没有（误导）`。
第三类更阴：**`lv_font_get_glyph_dsc()` 查得到、`charset.txt` 也写着有、但字形位图是空的**
（源字体把某些符号映射成了空轮廓）。屏上当然也是一片空白。
实测中招的是 **`…` U+2026（省略号）**：用户报"搜索后面有一个字符没正常显示"，
我先按"缺码点"查了一遍（不是），最后是加了 box 尺寸检查才认出来。

**判定方法**（已做成开机自检，`tools/gen_ui_text.py` + `ui_font_audit_text()`）：
```c
lv_font_get_glyph_dsc(font, &d, cp, 0) && d.box_w > 0 && d.box_h > 0   /* 三个都要满足 */
```
只要 box_w/box_h 是 0，屏上就画不出东西，和"没有这个码点"一样糟。

**顺带记这个自检工具**：`tools/gen_ui_text.py` 扫 UI 源码里的**字符串字面量**
（跳过注释）抽出所有非 ASCII 字符 → 生成 `ui_text_chars.h` → 固件开机逐个查字体，
缺谁报谁。⚠️ 它自己的日志和探针串必须是纯 ASCII，否则下次生成会把它们也扫进来。
改了 UI 文案之后要重跑那个脚本。

**实测确认画不出来的符号**（探针每次开机都报）：
`… — × → ★ ▶ · ⚠`（即 U+2026 / U+2014 / U+00D7 / U+2192 / U+2605 / U+25B6 / U+00B7 / U+26A0）
—— 界面上要表达这些意思就用中文或 ASCII 代替（`...`、`(无标题)`、`x`、`->`）。
