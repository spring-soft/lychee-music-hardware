**2026-09-25 做的 M8**：屏上搜索（字母键盘 + 拼音输入法 + 结果页）+ 全机 K4 规则统一。
新增 `components/ui/src/ui_search.c`（三个页面）、`components/ui/src/ui_pinyin.c`（查表）、
`tools/gen_pinyin.py`（生成表）、`player` 的搜索命令、菜单"搜索"取代"播放/暂停"。

## 1. ⚠️⚠️ Navidrome 服务端【不支持拼音搜索】——这是整个设计的前提
实测你这台（0.63.2-SNAPSHOT）：`yue`/`ylkbd`/`zjl`/`caijianya`/`yuelaiyuebudong`
**全部 0 结果**；而中文「不懂」能找到「越来越不懂」→ **模糊搜索本身是好的，只是不认拼音**。
（WebSearch 也确认官方没有这功能，第三方镜像做的只是简繁转换。）
⚠️ 所以**"用字母搜中文歌"只能设备自己做**。用户否掉了"设备本地建索引"（他会一直加歌，
索引会过时），采用 **屏上拼音输入法**：设备把字母变成真汉字，再把汉字交给服务器搜 ——
**搜索始终由服务器做，新加的歌立刻能搜到**。

**顺带发现**：Navidrome 有个 `ND_SEARCHFULLSTRING` 选项管"能不能搜中间子串"（默认只从头匹配？
实测我们这台能搜中间，所以要么已开要么默认改了）。

## 2. 拼音表怎么造（`tools/gen_pinyin.py`）
数据源用**本机现成的**（不用联网、不用装包）：用户的中文输入法是 Rime 雾凇拼音，
`~/.local/share/fcitx5/rime/cn_dicts/` 下就是表：
- `8105.dict.yaml`（通用规范汉字表）格式 `汉字<TAB>拼音<TAB>权重` —— **权重直接当常用度**
- `41448.dict.yaml`（41448 字，**无权重**）只用来兜底补 8105 没覆盖的字
- 词典里还有**词语**条目，靠"只取单字"过滤掉

产物 `assets_src/pinyin/pinyin.bin`（19KB，`gen_assets.py` 用新增的 fmt=4 原始 blob 打包）：
`u32 magic "EPY1" + u16 音节数 + u32 候选数 + 音节表[407]×{name[8],off,cnt} + u16 码点数组`，
音节表按名字升序供二分查找，**每个音节内已按权重降序排好**。

**实测覆盖**：字库 6763 个汉字 **100% 覆盖**（8105 拿到 6653 = 98.4%，41448 补 137 字）；
407 音节 / 7290 条候选。抽查：`yue`→**越**月约跃岳悦、`lai`→**来**莱赖籁、`bu`→**不**部步布、
`dong`→动东洞**懂**、`hang`→**行**航杭（多音字也在，因为是按行存储的）。

⚠️ **两条必须遵守**：
- **只保留字库能显示的汉字**（与 `assets_src/font/charset.txt` 取交集）。字库缺字在屏上是
  【一片空白】而不是方框 —— 候选列表里混进一个看不见的字，用户选上去就是灾难。
- **字母格给的是大写 A-Z，表里全是小写** → 输入前必须转小写，否则
  `pinyin_is_prefix()` 全不匹配、**一个字母都打不进去**（我写完才发现的）。

## 3. 输入页的光标：一条线，不要两个区
光标是一条线性序列：`0..25 = A-Z ｜ 26 = 退格 ｜ 27 = 确定 ｜ 28.. = 候选字`。
**为什么不做"字母区/候选区两个独立光标"**：那样就得设计"怎么从候选区回去改字"，
一不小心就是陷阱（用户进了候选区，发现退格键够不着、也退不回来）。
一条线走下来，一直往左按就能从候选字倒回 确定 → 退格，**永远出得来**。

**省事的一步**：音节打完且再打字母也变不成更长的音节（yue/lai/bu/dong…）→
光标**自动跳到候选字**，常用情况就是"打字母 + K3 选字"两步；还能延长的
（yu → yuan/yue/yun）不跳，免得挡住继续打。想挑字也可以自己按 K2 走到"确定"。

## 4. ⚠️⚠️ 把 LVGL 控件挤出内部 RAM：`SPIRAM_MALLOC_ALWAYSINTERNAL`
加搜索页后设备直接崩了：`E BLE_INIT: Malloc failed` + `httpd_accept_conn: error in accept (113)`。
根因：**小于 4KB 的 malloc 一律进内部 RAM**（默认 `SPIRAM_MALLOC_ALWAYSINTERNAL=4096`），
而新页面有 **~67 个 LVGL 控件**（光字母格就 26 个标签），每个约 200~250 字节 → 内部 SRAM 被吃光。

**降到 512** 后控件/样式/小结构体都进 PSRAM（LVGL 控件树不需要内部 RAM —— 真正要 DMA 的
是画布，那两个缓冲是显式 `MALLOC_CAP_DMA|MALLOC_CAP_INTERNAL` 申请的，不受影响）。
结果**比加功能前还宽裕**："加载界面后" 134 KB → **152 KB**，全部起来后 11 KB → **17 KB**。
代价只是 LVGL 遍历控件树多走外部 RAM（实测 lv_timer 最坏仍在 7~16ms）。

## 5. 顺带修的两个 bug（都不是搜索本身，但都在同一片代码里）
- **搜不到东西报 502**：`get_song_list()` 在"解析成功但 0 条"时 `return ESP_FAIL`，
  于是 `h_search` 走 `err != ESP_OK && got == 0` 返回 502。
  实测 `zzzznotexist` → 502「Navidrome 不可达？」，而服务器好得很。
  **修法**：解析成功后一律返回 `ESP_OK`（0 条也是成功），"有没有歌"交给调用方看 `*got`。
  顺带修好另一种情况：**收藏为 0 首的用户**以前会被永久判成"拉收藏失败"。
- **⚠️ 长按 K4 进菜单再回来，封面消失**（用户报的）：`ui.c` 里从别的页面回来会走
  `s_play_refresh_all` 的 `force` 分支，那里**无条件把封面设回占位图**；而真封面只在
  "新封面刚解码好"（`s_cover_ready`）时才贴 —— 歌曲没变就不会重新触发，
  占位图一直挂到下一首歌。**修法**：force 分支优先复用
  `s_cover_dsc.data != NULL && s_cover_gen == st.gen` 的已解码封面。
  **验证手法**（不用按键）：`POST /api/hid {"on":true}` 切到蓝牙页再 `{"on":false}` 切回来 ——
  和"长按 K4 进菜单再回来"走的是同一段代码，日志里能看到"封面: 复用第 N 代已解码的封面"。

## 6. K4 规则统一
用户要求"短按回上一级、长按回播放器"。做法是 `ui_pages.c` 里一张**父页面映射**
`ui_page_parent()`，`key_short` 的 default 分支和 `key_long` 都用它，不再各页硬编码。
层级：MENU→PLAY，SRC/MENU 同级回 MENU，SEARCH_MODE→MENU，SEARCH_IN→SEARCH_MODE，
SEARCH_RES→SEARCH_IN（用户要的：方便改词重搜）。
⚠️ **播放页故意例外**（用户确认保持现状：短按换来源、长按进菜单）—— 它是最外层，没有上一级。
⚠️ 音量页的"来路"要用变量记住（`ui_vol_open()` 里存），因为既可能从菜单的"屏幕亮度"进、
也可能从播放页长按 K2 进、还可能是蓝牙遥控页 —— 以前一律回播放页，从菜单进也跳播放页，是错的。
⚠️ 搜索页的 `ui_search_key_short()` 里 **K4 必须 `return false` 放行**，吞掉就再也回不去了。

## 7. 一个 C 语言低级坑（浪费了一轮编译）
我在注释里写了 `把缓冲区强转成 u16*/结构体指针` —— **`*/` 把块注释提前结束了**，
后面的中文注释全被当成代码，报了一堆 `unknown type name '拼音表...'`。
写中文注释时留意 `*/` 这种序列。

## 9. 用户实机反馈后补的三件事（2026-09-25 晚）
- **`…` 就是那个"看不见的字符"**：用户装上新固件后确认"现在能看到了"。原因和判定方法见
  [[esp-music-fonts]] 第 6 条 —— **有码点但字形位图是空的**，我原来的自检查不出来，
  升级成"连 box 尺寸一起看"之后才认出来。
- **⚠️ 蓝牙控制页里"没连蓝牙时按 K4 退不出去"**（用户实测）：`bt_key_short()` 里
  "没连上就把按键吃掉"那段**把 K4 一起吞了**，于是卡在遥控页出不来。
  **修法：K4 必须在最前面处理，任何"吞按键"的逻辑都不能连出口一起吞。**
  ⚠️ 这和搜索页那条教训是同一个（`ui_search_key_short` 里 K4 要 `return false` 放行）——
  **以后凡是写"吞掉这个键"的逻辑，先问一句：出口键(K4)会不会被吞掉？**
- **蓝牙只在"遥控模式"里才广播**（用户要求"退出功能后不要再占用性能"+"保证音乐播放流畅"）：
  广播是**持续**开销（每 30~50ms 在 3 个信道各发一包，还要和 WiFi 抢 coex 时隙），
  开机就常开会影响音频流。改成 `hid_remote_set_mode()` 里开关广播：
  进模式 → `adv_setup()+adv_start()`；出模式 → `ble_gap_adv_stop()`。
  实测日志：`HID 已就绪（待机：进「蓝牙控制」页才广播）` → `广播中` → `已停止广播`。
  另外确认**搜索三页在离开页面后零开销**：`ui_search_tick()` 只在当前页是搜索页时才被调，
  拼音表是 mmap 只读、不进 RAM。
  实测退出蓝牙后连续 53 秒 **欠载 0**、SRAM 15KB 稳定。
