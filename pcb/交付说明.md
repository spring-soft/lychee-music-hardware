## 二、与规格书的三处偏离（均已获用户确认）

### 1. K1 从 GPIO3 改到 GPIO38 ★ 需要同步改固件

规格书把 K1 从 `IO3` 改到 `IO38`，避开 strapping 脚。但资料包里的
`固件引脚定义/board.h` 与旧备份 **md5 完全相同**（`e401d911…`），即固件没改过。
**若不改固件就烧录，K1 会直接失效**（固件轮询悬空的 IO3，永远读到"未按下"）。

→ 已交付固件补丁 `firmware-patch.diff`，见第五节。

### 2. 220µF 耳机耦合电容改用固态电容（规格书原要求物理上做不到）

规格书要求 **220µF / ≥10V / 1210 封装**，三个条件在立创库里凑不齐 ——
1210（3.2×2.5mm）封装下 220µF 的最高耐压只到 6.3V。改为：

`KNSCHA RST220UF10V018`，220µF/10V，`CAP-SMD_BD6.3-L6.6-W6.6-FD`，**C4747973**

比钽电容 ESR 更低、无压电噪声、**接反不会起火**。

### 3. 新增 4 颗 ES8388 退耦电容

规格书第 3.8 节写「未列出的脚悬空」，但 `VREF`(10)、`VMID`(20) 悬空会导致
工作点漂移/噪声 —— 原来那块 ES8388 音频模块把这些电容做在模块上了，画成单板就没
了。已新增（用户确认）：

| 位号 | 值 | 接 |
|---|---|---|
| C17 | 10µF | `VREF` → GND |
| C18 | 100nF | `VREF` → GND |
| C19 | 10µF | `VMID` → GND |
| C20 | 100nF | `VMID` → GND |

> `ADCVREF`(19) 仍悬空 —— ADC 已断电（`R_ADCPOWER=0xFF`），无影响。

## 四、耳机座引脚映射（已定案，含证据链）

用户确认耳机为**三环 4 极（TRRS）**，且不做麦克风。定案接法：

| J2 引脚 | 网络 | 说明 |
|---|---|---|
| 2 | `HP_L` | 尖端 = 左声道 |
| 3 | `HP_R` | 第一环 = 右声道 |
| 4 | 悬空 | 第二环 = 麦克风线，立体声不需要 |
| 5 | `GND` | 筒身 |

**证据链（三个独立来源互相印证）：**

1. **官方引脚图 SVG 的几何坐标**（从 LCSC 商品页取得原始 SVG）
   引脚 5 的走线 `(390,290)→(350,290)→(350,300)`，终点正落在筒身矩形条
   `x:347-353, y:300-318` 的左上角 → **引脚 5 在结构上就是筒身**。

2. **触点深度排序**：三个弹簧触点向左伸出至 x=359(引脚2)、368(引脚3)、373(引脚4)。
   耳机插头插入时**尖端走得最深** → 最深者(引脚2)为尖端。

3. **KiCad 参考库**（源自数据手册）：`Sleeve=1 / Tip=2 / Ring1=3 / Ring2=4`
   —— 引脚 2/3/4 的命名与上面两项分析完全一致。

**残余风险**：引脚 5=地 是结构性证据，置信度高。万一判错，耳机输出串有 220µF
耦合电容、直流被隔断，**最坏情况是某声道无声，不会损坏芯片**。引脚 2/3 若左右
搞反，调换两个耦合电容接线即可。

## 五、ERC 的 5 条警告（不影响电气正确性）

排查过程：最初 330 条警告，逐项定性后发现**主要是元件超出图框**导致的
（`zoomToAllPrimitives` 渲染可见元件全在图框外）。换成 A1 图幅、元件全部入框后
降到 7 条；耳机座接完线后降到 **5 条**。

剩余 5 条来自规格书明确要求悬空的脚（ES8388 的 ASDOUT / LIN / RIN、
USB 的 SBU1/SBU2、屏排线 NC 等）。

`SCH_Drc.check()` 只返回 `{type,count}` 聚合值，不提供逐条文本，需在 EDA 的
DRC 面板（工具 → 电气规则检查）查看中文明细。

## 六、固件补丁（`firmware-patch.diff`）

针对 `esp-music/components/board/{include/board.h, src/board.c}`，共 44 行改动。

**用法**（在 esp-music 工程根目录）：
```bash
patch -p1 < firmware-patch.diff
```

已验证：`patch -p1 --dry-run` 干净通过，应用后结果逐字节一致。

### 改动内容

| # | 文件 | 改动 |
|---|---|---|
| 1 | board.h | `BOARD_PIN_KEY1` **3 → 38** |
| 2 | board.h | 删除 `BOARD_PIN_I2S_DIN`（不录音，IO38 腾给 K1） |
| 3 | board.h | 删除 `BOARD_PIN_PA_EN`（无 PAM8406 功放） |
| 4 | board.c | `board_pa_enable()` 改空实现（保留签名兼容调用方） |
| 5 | board.c | I2S `din` → `I2S_GPIO_UNUSED`（通道本就是 TX-only：`i2s_new_channel(&chan_cfg, &s_tx, NULL)`） |
| 6 | board.c | 删除 PA 使能脚的 GPIO 初始化 |
| 7 | board.c | 自检日志去掉 PA / DIN 两项 |

**已复查**：改完后 `BOARD_PIN_I2S_DIN` / `BOARD_PIN_PA_EN` 在全文件**零残留引用**。

⚠️ 补丁只覆盖 `board.c` / `board.h` 两个文件。`BOARD_PIN_KEY1` 的实际使用点在
`components/ui/src/ui_keys.c`，该文件不在资料包内 —— **但它是通过宏引用的，
只要 board.h 改了就会自动生效，无需改 ui_keys.c**。
