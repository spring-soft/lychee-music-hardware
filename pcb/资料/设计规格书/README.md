# ESP-Music PCB 设计包 · 从这里开始

---

# 一、这台设备是什么？

## 1.1 一句话

**一台放在桌上、连上家里 WiFi、用耳机听自己音乐库的小播放器。**

## 1.2 它解决什么问题

你家电脑 / NAS / 树莓派上跑着一个 **Navidrome**（开源的自建音乐服务器），里面存着你收藏的全部歌曲。

想听歌的时候：

| 传统做法 | ESP-Music |
|---|---|
| 打开电脑 → 等开机 → 打开网页/客户端 → 找歌 | **插上耳机就能听** |
| 或者掏手机 → 解锁 → 打开 App → 连服务器 | 按键切歌，不看手机 |

**它就是一台"专用音乐终端"** —— 不干别的，只为听歌。

## 1.3 长什么样

```
        ┌─────────────────────────────┐
        │  ┌───────────────────────┐  │
        │  │                       │  │
        │  │   1.8 寸彩屏 128×160  │  │   ← 显示歌名、封面、歌词、进度条
        │  │                       │  │
        │  └───────────────────────┘  │
        │                             │
        │   [K1]  [K2]  [K3]  [K4]    │   ← 4 个按键
        │                             │
        │  ○耳机孔            [Type-C] │   ← 板边：3.5mm 耳机口 + Type-C
        └─────────────────────────────┘
            约 60 × 45 mm，巴掌大
```

## 1.4 怎么用（用户操作流程）

```
1. 插上 Type-C 线供电
      ↓  屏幕亮起，出现启动动画
2. 自动连上你家的 WiFi
      ↓
3. 自动连上你的 Navidrome 服务器
      ↓
4. 自动接着上次听的歌、上次的位置继续放
      ↓
5. 插上耳机就能听
```

**全程不需要任何设置**（WiFi 和服务器地址之前配过一次，存在设备里）。

## 1.5 屏幕显示什么

```
┌─────────────────────────────┐
│ ♪ 越来越不懂                 │  ← 歌名（只显歌名，不带歌手）
│ ┌────────┐                  │
│ │        │  窗外的雨 淋湿了  │  ← 歌词（3 行，当前行高亮）
│ │ 封面   │  我的眼睛          │
│ │        │  我却看不清        │
│ └────────┘                  │
│ ████████░░░░░░  01:23/04:12 │  ← 进度条 + 时间
└─────────────────────────────┘
```

## 1.6 四个按键干什么

| 按键 | 短按 | 长按 |
|---|---|---|
| **K1** | 下一首 | 收藏 / 取消收藏这首歌 |
| **K2** | 播放 / 暂停 | 进入音量调节 |
| **K3** | 上一首 | 打开歌曲列表 |
| **K4** | 切换显示模式（封面+歌词 / 全屏歌词 / 全屏封面） | 打开主菜单 |

**主菜单**里还有：蓝牙遥控、切换音乐来源（最近播放/我的收藏/随机30首）、**屏上搜索**、屏幕亮度、重连 WiFi、系统信息。

## 1.7 还能干什么

| 功能 | 说明 |
|---|---|
| **手机网页控制台** | 手机连上它的 WiFi 或和它同一个局域网，浏览器打开它的 IP 就能选歌、拖进度、看封面 |
| **蓝牙遥控** | 打开"蓝牙遥控"模式后，它会变成蓝牙键盘，**K1~K4 摇身变成控制手机/电脑播放的遥控器** |
| **屏上搜索** | 用 4 个按键在屏幕上打拼音搜歌（设备自带拼音输入法，因为服务器不支持拼音搜索） |
| **收藏双向同步** | 设备上收藏的歌，会同步到 Navidrome 服务器 |

## 1.8 为什么要重新画板

现在的硬件是在**面包板上用杜邦线**连起来的（开发板 + 音频模块 + 屏幕模块各自一块小板），有三个问题：

| 问题 | 现象 |
|---|---|
| **接触不良** | 听歌时断断续续的咔哒声 |
| **音质差** | 没有地平面、杜邦线当天线、功放的开关噪声串进模拟通路 → 底噪大 |
| **不可靠** | 松散、碰一下就断、做不成成品 |

**画一块 PCB 能同时解决这三个问题**：完整地平面 + 短走线 + 焊接替代插接。

## 1.9 新板和旧硬件的区别

| | 旧（面包板） | 新（自制 PCB） |
|---|---|---|
| 主控 | 整块开发板（ESP32-S3-COREBOARD V1.4） | **裸模组** ESP32-S3-WROOM-1-N16R8 |
| 音频 | ES8388 模块 + **PAM8406 功放 + 喇叭** | **ES8388 直接推耳机**，删掉功放和喇叭 |
| 屏幕 | 8 针模块 + 排母 | **1.8" 裸屏 + FPC 座** |
| 连接 | 杜邦线 | **PCB 走线** |

> **为什么删掉功放**：用户只要耳机不要喇叭。而且 **D 类功放的开关噪声正是耳机底噪的主要来源**，删掉等于从根上消除噪声。ES8388 本身内置 40mW 耳机功放，直接就能推 16Ω/32Ω 耳机。

# 五、最终要做出来的东西

```
一块约 60 × 45 mm 的 4 层板，焊好约 45 个元件：

  ┌ ESP32-S3-WROOM-1-N16R8 模组     主控 + WiFi + 蓝牙
  ├ ES8388                          音频 Codec（内置耳机功放）
  ├ TLV75733 LDO                    5V → 3.3V
  ├ Type-C 座                       供电 + 烧录 + 串口 + JTAG
  ├ 3.5mm 立体声耳机座
  ├ FPC 座（0.5mm 14P）             接 1.8" 屏
  ├ 背光 MOSFET + 限流电阻
  ├ 6 个轻触开关                    K1-K4 + RESET + BOOT
  └ 约 32 个电阻电容磁珠

插上屏 → 插上耳机 → 插上 USB 线烧固件 → 就能听歌
```

**制造方式**：嘉立创一站式（PCB 打样 + SMT 贴片 + 插件焊接），到手即成品板。

# 六、⚠️ 三条最容易翻车的地方

| # | 注意 | 后果 |
|---|---|---|
| 1 | **模组天线区正下方不能铺铜，且要悬出板边** | 铜在天线下面 → WiFi 辐射效率大幅下降，信号差、卡顿 |
| 2 | **`IO35` / `IO36` / `IO37` 绝对不能接任何东西** | 被 Octal PSRAM 芯片内部占用。网上例程用的是 N8R2（Quad PSRAM）版本，那三根能用，**不能照抄** |
| 3 | **ES8388 的 `CE` 脚必须接 `VCC`** | 决定 I2C 地址（CE=1 → 0x11，正是固件用的）。接错 → 芯片完全无响应 |

（完整清单见规格书第 11 节）
