## 二、叠层设计（四层）

| 层 | ID | 用途 | 说明 |
|---|---|---|---|
| 顶层 Top | 1 | 信号 + GND 铺铜 | 元件少（只 14 个），中间大片空白走线 |
| 内层一 Inner1 | 15 | **VCC 3.3V 电源平面** | 整板铺铜，天线区挖空 |
| 内层二 Inner2 | 16 | **GND 地平面** | 紧贴底层，底层所有信号的完整回流路径 |
| 底层 Bottom | 2 | 信号 + GND 铺铜 | ESP32 / 音频芯片 / 电源都在这层 |

**为什么这么分：**

- **内层二做地平面** —— 它紧贴底层，而 ESP32、ES8388 音频芯片、IP5306 电源全在底层。这层做完整地平面 = 所有信号都有完整回流路径，**这是解决底噪最关键的一步**。
- **内层一做 VCC 平面** —— 见第四节的「VCC 阻抗问题」。

**天线禁布区**：板子上边缘留出 84 mil（约 2.1 mm）不铺铜（所有层），避让 ESP32 模组的 WiFi 天线。同时模组天线本身悬出板边。

## 三、本轮修掉的 4 处间距违规

DRC 在布局阶段查出 4 处，**全部是我之前的检查脚本漏掉的** —— 根源是我用「手写的元件本体尺寸表」估算，而编码器、耳机座的**焊盘伸出了本体轮廓之外**。

| # | 问题 | 处理 |
|---|---|---|
| 1 | `C15` ↔ `C16` 焊盘重叠 **16.4 mil** | C15 → (1572, 1330)，C16 → (1560, 1070) |
| 2 | `J4` 电池座固定脚 ↔ `R17` 焊盘，间隙仅 **1.2 mil** | R17 左移到 x=1990 |
| 3 | `J2` 耳机座焊盘**出界 11.8 mil** | J2 左移到 x=2125 |
| 4 | `EC1` 编码器焊盘**出界 5.9 mil** | EC1 左移到 x=2070 |

**改进**：新增 `check-pads.mjs` —— 直接用 EDA 导出的**真实焊盘几何**（形状 + 旋转角）算矩形，不再依赖手写尺寸表。修完复跑，它与 DRC 的结果**完全一致**。

另外修掉的盲区：
- `check-throughhole.js` 改为**自动识别直插件**（读焊盘 layer=12），不再手写清单 —— 之前 SW5/SW6 改成贴片后清单没同步
- 各检查脚本里 SW5/SW6 的本体尺寸从 6×6mm 修正为实际的 4.0×2.9mm

## 四、电源设计的一处取舍（请你知悉）

### VCC 阻抗问题 —— 已解决

自动布线把 VCC 走成了 **223 mm 长的 10 mil 细线**。按 1 oz 铜算：

```
电阻 ≈ 0.51 Ω  →  ESP32-S3 峰值 500mA 时压降 0.26V  →  会欠压复位
```

**解决方式**：内层一铺整板 VCC 平面，并打 2 个接入孔接到最关键的节点
（`U3.5` LDO 输出端、`U1.2` ESP32 供电端），另有自动布线顺手打的 8 个 VCC 过孔。
平面把长距离电流的阻抗降了一个数量级。

### 电源线宽 —— 保持 10 mil

`BAT+`/`VBUS`/`+5V` 没能加粗。原因：**自动布线按最小间距密排，事后加粗没有空间**（我写脚本实测了每一段到邻线的距离，88 段里**没有一段**有加宽余量）。

不过按实际电流算，**10 mil 够用**：

| 网络 | 长度 | 估算电流 | 压降 | 判断 |
|---|---|---|---|---|
| `BAT+` | 41.4 mm | ~0.6 A | 47 mV | ✅ |
| `+5V` | 64.8 mm | ~0.4 A | 50 mV | ✅ |
| `VBUS` | 61.5 mm | ~1 A（充电） | 117 mV | ✅ |

> 试过在布线前把线宽规则写进「设计规则」，但**自动布线过程会把网络规则重置回 default**，所以没生效。

### GND 缝合

53 个 GND 过孔均匀分布板面，把顶层/底层的 GND 铺铜与内层二地平面缝合。

## 五、布局上的两处外观调整

1. **编码器与按键对齐**（你要求的）
   `EC1` 从 y=250 下移到 **y=195**。原因是这个封装
   （`SW-SMD_HYCW03-2.8D-5P-S`）的**焊盘中心与画出来的本体外形不同心** ——
   焊盘本来就在按键中线上，但外形框偏上约 55 mil。按视觉外形对齐后，本体与
   `SW1~SW4` 的方框上下边缘齐平。焊盘偏移 55 mil 对贴片无影响。

2. **编码器与按键同一行**
   `EC1` x = 2070，与 `SW1~SW4`（x = 500/900/1300/1700）同排，位于 LED 列（x=2080）附近。

### 值得记下的 API 坑

嘉立创EDA专业版 V4.1.60 的 Run API Gateway 扩展里，以下接口**不可用或行为异常**：

| 接口 | 现象 |
|---|---|
| **`pcb_Document.save()`** | ⚠️ **改完必须调用**。文档会从磁盘重新加载，不保存的接口改动一刷新就回退。症状：脚本里明明创建成功并回读确认，下一次调用却变回原样。**本次因此白丢了两轮自动布线** |
| `pcb_Document.autoRouting()` | 调用后**永不返回**（界面点按钮正常） |
| `pcb_ManufactureData.getDsnFile()` | 导出的 DSN **所有元件坐标都是 0** |
| `pcb_Drc.createNetClass()` | 建不了网络类 |
| `pcb_PrimitivePour.create()` | 只在**闭合点串格式**下可用；`['R',x,y,w,h]` 格式算出的多边形是畸形的 |
| 铺铜填充计算 | API 建完边框后**不会自动算填充**，必须在界面点「重建铺铜」 |
| `pcb_Drc.overwriteNetRules()` | 能写入，但**自动布线时会被重置** |
| 请求超时 | 桥接服务器默认 30 秒，长任务需调 `EDA_BRIDGE_TIMEOUT_MS` |

**另外**：
- 每个脚本开头必须显式 `openDocument()`，否则 `getAll()` 返回 null
- 工程里可能有多个 PCB 文档，**`getAllPcbsInfo()[0]` 的顺序会变** —— 必须用 uuid 显式锁定目标板
- 移动 PCB 元件**会把已有走线全部清空**，布局微调必须在布线之前做完
- 铺铜的填充计算**接口做不了**，必须在界面点「重建铺铜」

### 可靠的工作流（本次验证过）

```
1. 接口改动 → await eda.pcb_Document.save()
2. 切到别的文档再切回来 → 回读校验（确认改动落盘）
3. 界面上做的操作（自动布线 / 重建铺铜）→ 让用户按一次 Ctrl+S
4. 再做第 2 步校验
```

**校验通过再进行下一步** —— 否则可能做完全部工作才发现某一环丢了。
